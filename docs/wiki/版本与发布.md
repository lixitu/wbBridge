本页说明 WB Bridge 的版本号规则、版本落点、校验方式与发布流程。事实来源：根 `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`src-tauri/core/Cargo.toml`、`src-tauri/core/src/orchestration.rs`、`scripts/*.mjs`、`docs/version/README.md`、`.github/workflows/release.yml`、`AGENTS.md`。

## 校验与推进

```bash
npm run version:check                 # 校验 5 处落点一致，否则退出码 1
npm run version:set -- <x.y.z>        # 同步改写各落点
```

`version:check`（`scripts/check-version.mjs`）校验 **5 处**：`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`，以及 `AGENTS.md` 的两行基准表。`release.yml` 的测试 job 也声明了同一脚本，**但该工作流迁移后尚未在 CI 实际运行**，因此「CI 已核验」目前不成立；改动版本号后建议再 `grep -rn "1\.0\.0"` 人工扫一遍文档。

## 版本号规则（写死）

- 版本号以**根 `package.json`** 为唯一来源；`src-tauri/core/Cargo.toml` 的 `0.1.0` 是 crate 内部版本，`status.json` 的 `0.2.0` 是历史沿革值，**两者都不得在无用户指令的情况下静默改动**。
- **仅当**新增了与现有问题**不同类、不同根因**的功能 / 修复，且**用户明确允许**推进版本号时，才可末位 +1。
- **以下情形绝对禁止推进版本号**：
  1. 同一问题的多轮往返排查与再次修复；
  2. 用户明确要求"不修改版本号 / 回退到 X.Y.Z"；
  3. 同一自然日对同一模块 / 同一类 bug 的追加修复；
  4. 纯 `docs/`、`README.md`、`AGENTS.md` 等文档类改动；
  5. 纯文案、注释、日志措辞、去抖等不引入新逻辑分支的打磨；
  6. 移植 / 迁移过程中的等价实现（行为未变即版本未变）。
- 用户要求"回退到 X.Y.Z"时，所有落点必须一致改写为用户指定值，本回合内不得再以"我刚改了代码所以 +1"为由推进。

> 界面调整同样不推进版本号：2026-10-01 的面板布局改造（侧栏分组导航、详情改为右侧常驻分栏、默认窗口 980×680 → 1120×720、侧栏 `--sidebar-w` 224 → 208px、新增 `--muted-strong`）属同一未发布版本内的界面调整，已在 `docs/version/RELEASE-v1.0.md` 的 v1.0.0 分节留痕。
> 后续说明（2026-10-01 同日）：该轮留下的 4 个「规划中」入口已在同日后续轮次实现（侧栏 5 入口全部可点，新增壳命令 `read_log` 与 `status.json` 顶层 `usage`），本版本内同样不推进版本号；证据见 `docs/validation.md`。
> 版本推进（2026-10-01 同日第八轮）：用户在本次**明确要求推进版本号**后，产品版本 `1.0.0 → 1.0.1`（5 处落点一致，`npm run version:check` 通过）；v1.0.0 分节从未发布，内容并入本次。依据见 `docs/version/RELEASE-v1.0.md` 顶部 v1.0.1 分节与 `docs/validation.md` 同轮条目。

### CI 工作流

`.github/workflows/release.yml`：推送 `v*` tag 或手动 `dispatch` 触发。

1. **test 作业**：跑 `cargo test`（核心）+ `check-version.mjs`，外加一道**「触发标签 ↔ `src-tauri/tauri.conf.json` 版本」闸门**（标签指向未推进版本的提交时直接失败）。
2. **平台构建作业**（macOS / Windows / Linux 各 2 架构）：`npm ci` + `tauri-apps/tauri-action`（带 `--target <triple>`）出 bundle，并注入签名环境变量。
   - macOS 作业在上传前多一步**「给 macOS 更新包补架构后缀」**：tauri 实测产出的更新包叫 `WB Bridge.app.tar.gz`（无版本、无架构），两个 mac runner 会往同一 Release 传**同名**资产、后者静默覆盖前者，因此统一改名为 `WB Bridge_<arch>.app.tar.gz`（`.sig` 同步改名——minisign 签的是内容不是文件名）。
3. **update-manifest 作业**（末位、`latest.json` 的唯一写者）：下载六平台产物 → `node scripts/gen-latest-json.mjs --dir artifacts --out latest.json` → 上传清单到 Release。`tauri-action` 自带的清单生成已用 `includeUpdaterJson: false` 关闭（6 个并发作业各写一次会互相覆盖、静默漏平台）。
4. 产物：六平台（macOS ARM/Intel、Windows x64/ARM、Linux x64/ARM）安装包 + 各自 `.sig` + `latest.json`，发布为 **Draft Release**；人工确认后再点 Publish。

> ⚠ 如实说明：核心 Rust 化后重写的 `release.yml` **从未在 CI 上实际运行过**；README 中关于「CI 构建」的历史构建结论均属迁移前记录。

### 签名与自动更新

- **自动更新已接线**：`src-tauri/Cargo.toml` 有 `tauri-plugin-updater` + `tauri-plugin-process`，`lib.rs` 的 builder 链注册两者，`tauri.conf.json` 有 `bundle.createUpdaterArtifacts: true` 与 `plugins.updater`（内联 `pubkey` + `endpoints` 指向 `https://github.com/trexwb/wbBridge/releases/latest/download/latest.json`）；capabilities 声明 `updater:default` + `process:allow-restart`（刻意不用 `process:default`，它含 `allow-exit`，会让 WebView 绕过 `quit_app` 的优雅关停链）。
  - **签名变量分工（实测）**：`tauri build|bundle` **只读 `TAURI_SIGNING_PRIVATE_KEY`**，值可以是私钥全文**或私钥文件的绝对路径**；`TAURI_SIGNING_PRIVATE_KEY_PATH` 只对 `tauri signer sign` 生效（等价于 `-f`）。`signer sign -k` 要的是**私钥字符串**，误传路径会报 `failed to decode base64 secret key: Invalid symbol 46`。CI 用 GitHub **Secrets** 存私钥全文 + 密码。
  - **密钥现状**：wbBridge 专用钥 `~/.tauri/wbBridge-updater-20261001.key`（`0600`、无密码、key ID `126D4E208E0F17BA`），公钥已内嵌配置。历史文件 `~/.tauri/wbBridge-updater.key`（key ID `2B11F78BEA8A43F`，权限同样 `0600`）密码未知且与现 pubkey 不配对，**已弃用、未删除**。⚠ 本机遗留：`~/.tauri/wbBridge.env` 与仓库本地 `.env` 的权限是 `0644` 且含非空 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`（两者都只被本地读取，`.env` 已在 `.gitignore` 内、`git ls-files` 确认未入库）——建议把这两个文件收紧到 `0600`，属**用户自行操作**，Agent 不改动仓库外凭据。🔴 换钥必须同步替换 `plugins.updater.pubkey`，否则老客户端验签必失败；私钥绝不入库、不进日志、不进 `status.json`，`.env.local` 严禁提交。
  - **Draft 语义**：`releaseDraft: true` 时 GitHub 的 `releases/latest` **不含 draft 与 prerelease** → 人工点 Publish 之前客户端检查更新必然 404，这是期望行为（draft 即灰度闸门）。
  - **v1.0.1 及更早版本收不到更新**：那一版没接线 updater，必须由用户手动下载安装包升级一次；自动更新链路只能从 **v1.0.2 → v1.0.3** 起验证。
- `latest.json` **只有一个写者**：CI 末尾的 `update-manifest` 作业跑 `node scripts/gen-latest-json.mjs --dir artifacts --out latest.json`（平台键取自 artifact **目录名**里的 target triple；默认要求六平台齐全、缺一即退出 1；mac 资产缺架构后缀同样失败）。本地也可跑：`npm run gen:latest`。
- 环境变量模板：`.env.example` → 复制为 `.env.local`（`.env.local` 已被 `.gitignore` 忽略，**严禁提交**）。这是唯一模板落点。
- 密钥生成 / 单独签名（`@tauri-apps/cli` 已在根 devDependencies）：
  ```bash
  npm run tauri -- signer generate -p '' -w ~/.tauri/wbBridge-updater-<日期>.key
  npm run tauri -- signer sign -f ~/.tauri/wbBridge-updater-<日期>.key -p '' '<产物路径>'
  ```

### macOS 首次打开

应用使用 ad-hoc 签名（未做 Apple 公证）。首次打开若被拦截：先尝试打开，再到「系统设置 → 隐私与安全性」点击「仍要打开」；若提示「已损坏」，确认来源可信后执行：

```sh
xattr -dr com.apple.quarantine "/Applications/WB Bridge.app"
```

## 版本日志约定（`docs/version/`）

- **命名**：`RELEASE-v{主版本}.md`（v1.0.x → `RELEASE-v1.0.md`，v1.1.x → `RELEASE-v1.1.md`）；GitHub Release 正文另用 `RELEASE-NOTES-v{完整版本}.md`。
- **按主版本一个文件**：次版本迭代作为分节追加到文件顶部（最新在前）。
- **发布前**在对应主版本文件追加该次版本分节；**发布后**分节状态标记 ✅ 已发布；本目录内已发布内容**只增不改**。
- **即使不推进版本号，也必须追加发布日志**：对应主版本文件顶部新分节，注明日期与"不推进版本号"。
- GitHub Release 正文按完整版本单独成文：`RELEASE-NOTES-v{完整版本}.md`。
- 目录内现有文件（2026-10-01 实读）：`README.md`（索引与落点）、`RELEASE-v1.0.md`（v1.0.1 + v1.0.0 两个分节，均 📝 待发布）、`RELEASE-NOTES-v1.0.1.md`（本版 GitHub Release 正文）。`RELEASE-NOTES-v1.0.0.md` 已从工作区删除（v1.0.0 从未发布，其内容并入 v1.0.1 说明）。
