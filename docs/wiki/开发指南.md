# 开发指南

本页面向参与 WB Bridge 开发的贡献者，内容以 `AGENTS.md`（项目强制规范）与根 `package.json`、`docs/version/README.md` 的实读结果为准。

## 环境要求

- **Rust** stable（核心 `src-tauri/core/Cargo.toml` 声明 `rust-version = "1.75"`；壳 `src-tauri/Cargo.toml` 声明 `rust-version = "1.77"`）。
- **Node.js >= 24**（根 `package.json` 的 `engines`）——**只**为 Vite 前端构建与 `scripts/*.mjs` 版本脚本服务，核心运行不依赖它。
  - 本机由 nvm 管理时，**非登录 shell 的 PATH 中可能没有 `node`**，执行 npm 命令前先载入：
    ```bash
    export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"
    ```
- **Linux 构建系统包**：`libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf libssl-dev`。

## 安装依赖与常用命令

```bash
npm install
```

| 目的 | 命令 | 执行目录 |
|---|---|---|
| 安装前端依赖 | `npm install` | 仓库根 |
| 运行全部核心测试 | `cargo test` 或 `npm test` | `src-tauri/core/` |
| 核心编译检查 | `npm run rust:check`（= `cargo check --manifest-path src-tauri/core/Cargo.toml`） | 仓库根 |
| 静态检查（核心） | `cargo clippy --all-targets` | `src-tauri/core/` |
| 静态检查（壳） | `cargo clippy --no-deps` | `src-tauri/` |
| 面板 lint | `npm run lint`（= `eslint .`） | 仓库根 |
| 启动核心（独立进程，调试用） | `cargo run --manifest-path src-tauri/core/Cargo.toml --bin wbbridge-core` | 仓库根 |
| 开发桌面应用 | `npm run dev` / `npm run tauri:dev`（= `tauri dev`，`beforeDevCommand` 拉起 `vite:dev` → `http://localhost:41990`） | 仓库根 |
| 构建前端产物 | `npm run vite:build` | 仓库根 |
| 构建桌面应用 | `npm run build`（= `vite:build && tauri build`） | 仓库根 |
| 版本一致性校验 | `npm run version:check` | 仓库根 |
| 版本推进 | `npm run version:set -- <x.y.z>` | 仓库根 |

> Rust 侧命令一律带 `--manifest-path src-tauri/core/Cargo.toml` 或进入 `src-tauri/`；全部 Rust 代码都在 `src-tauri/` 下（壳 = `src-tauri/src/`，核心 = `src-tauri/core/`）。**不存在** Node 版的 `src/core/` 后端与根级 `core/`（那是已归档的 JS 核心）。

## 源码构建与调试

### 构建桌面应用

```bash
npm run build      # vite:build && tauri build，产物在 src-tauri/target/*/release/bundle/
```

### 单独运行核心（调试）

核心可脱离桌面壳独立运行（同一份编排代码）：

```bash
cargo run --manifest-path src-tauri/core/Cargo.toml --bin wbbridge-core
```

启动后监听 `127.0.0.1:41980`（`BUDDY_PORT` 覆盖），数据目录走平台默认值。

### 健康检查与模型列表

```bash
# 独立核心二进制（平台默认目录）
curl -H "Authorization: Bearer $(cat "$HOME/Library/Application Support/Buddy Bridge/api-key")" \
     http://127.0.0.1:41980/health

# 列出已发布模型（id 形如 `OC · 名称`）
curl -H "Authorization: Bearer <key>" http://127.0.0.1:41980/v1/models
```

`/health` **同样需要 Bearer 鉴权**（无 key 返回 401）。桌面壳形态的数据目录是 Tauri `app_data_dir`（macOS `~/Library/Application Support/app.wbbridge.desktop`），端口见同目录 `status.json` 的 `endpoint`。

### 核心环境变量

| 变量 | 默认值 | 作用 |
|---|---|---|
| `BUDDY_PORT` | `41980` | HTTP 端口；非 1024–65535 的整数直接失败退出（嵌入壳时由壳显式传入 `StartOptions.port`，不读环境变量） |
| `BUDDY_DATA_DIR` | 平台数据目录 | 覆盖数据目录（嵌入壳时由 `StartOptions.data_dir` 注入 app_data_dir） |
| `BUDDY_MODELS_FILE` | macOS/Linux `~/.workbuddy/models.json` | 覆盖 WorkBuddy 配置文件路径（Windows 走"已保存值 → 发现"流程） |
| `BUDDY_NO_SYNC` | 未设置 | `=1` 时跳过启动导入与后续模型同步 |
| `BUDDY_OPENCODE_PATH` | 无 | 首选 OpenCode 可执行文件路径（优先级最高） |
| `BUDDY_PARENT_PID` | 无 | 父进程 pid；父进程消失则核心自行优雅关停 |

> 嵌入壳时**禁止**用 `std::env::set_var` 改变进程级配置（不安全、与并发冲突）；必须走 `orchestration::run(StartOptions { data_dir, port, handle_signals })`。

## 测试与质量基线

- 核心测试全部用 Rust：`cargo test`（`src-tauri/core/`）。基线 **207 通过 / 0 失败**（约 0.3s）：
  - lib 单元测试 **187**（含 `src/*.rs` 内 `#[cfg(test)]`）；
  - `tests/js_parity.rs` **11**（每模块一组，比较 `tests/fixtures/*.json` 冻结的 `expected`）；
  - `tests/red_lines.rs` **9**（运行期红线守卫）。
- 壳（`src-tauri/`）另有 `cargo test --lib` **8 通过 / 0 失败**：日志尾部读取 4 项 + `shell_action_routes_match_the_core_contract`
  （实读 `ADMIN_ROUTES` 与核心 `ACTION_ROUTES` 断言逐项一致）+ 退出链路 3 项（`repeated_quit_requests_stop_only_once`、
  `a_quit_requested_shutdown_is_not_reported_as_failure`、`service_down_reports_only_real_failures`）。
- **JS↔Rust 对拍已快照化**：`tests/fixtures/*.json` 共 **11 个模块 / 271 个用例**，每个用例带 `expected` 黄金快照（迁移前由 JS 实现录制，已抹平随机 id / `created` / `ms` / sync 文案；沙箱绝对路径在比较前还原成 `$BASE` 占位符，快照不绑定机器与目录布局）。**默认不启动 Node**。
  - 需要重新录制时：把仓库外归档 `backup/wbBridge-node-20261001/` 的 `core/` 与 `core-rs-tests-js/`（归档内目录名，放回后即 `tests/js/`）放回原位，再执行 `WB_PARITY_RECORD=1 cargo test --test js_parity`。
  - **禁止**在没有 JS 真相的情况下手工编辑 `expected` 来"让测试通过"。
- **测试严禁真实联网、真实下载**：网络与运行时行为必须通过注入点替换（`RuntimeOptions` 的 `FetchFn`/`LatestFn`/`ProbeFn`、`SyncIo`、`atomic::replace_with_retry_with`）。
- 新增 / 修改行为必须补测试；触碰安全、供应链、数据红线时，优先在 `tests/red_lines.rs` 补断言而不是只写文档。
- 修改 `src-tauri/core/src/` 后必须运行 `cargo test` 并报告**实际**通过 / 失败数量，**不得以"应该能过"代替执行**；`cargo clippy --all-targets` 必须保持 **0 warning**。
- `cargo fmt --check` 全仓并不干净（**未作为门禁**），代码风格以 clippy 0 warning 为准；勿在无关文件上顺手格式化。

## 编码规范要点

### Rust 核心

- `src-tauri/core/` 是**纯 Rust、无 Node 依赖**；edition 2021。
- 跨语言语义对齐靠 `json.rs` 的 JS 等价原语（`truthy`、`strict_eq`、`js_stringify`、`Env`）与 `serde_json` 的 `preserve_order`；**不得改用无序 map**（键序是 `models.json` 合并语义的一部分）。
- 新增运行期依赖必须说明理由；禁止把任何 Node 运行时、pkg、esbuild 重新引入核心链路。
- 异步一律 `async/await` + tokio；共享可变状态用 `Arc<Mutex<..>>` / 原子量，串行写链（`Slot` + `CHAIN_SEQ`）不得改成并发写。
- 业务错误统一 `BridgeError { message, status, code }`（`protocol.rs`），不得吞掉错误或返回无码错误。
- 注释写**为什么**，不写"是什么"；平台差异集中在 `platform.rs` / `system_proxy.rs` / `runtime.rs`，业务代码不得散落平台判断。
- 日志只写非敏感信息；**严禁**把 `api-key`、`OPENCODE_SERVER_PASSWORD`、用户凭据写入日志或 `status.json`。
- 文件写入优先走 `atomic.rs::replace_with_retry` 或 `sync.rs::atomic_write`，禁止裸 `rename` 覆盖；新建目录 / 敏感文件显式权限（目录 `0700`、密钥文件 `0600`）。

### UI 规范（2026-10-01 面板改造后）

- 面板 = Vue 3 SFC + Vite 构建产物 `dist/`，由 Tauri WebView 加载；**不得引入 CDN 或任何外部请求**，必须满足 `tauri.conf.json` 的 CSP（`default-src 'self'`、`script-src 'self'`、`connect-src ipc: http://ipc.localhost`）。
- 与壳的通信只走既有契约 `src/core/bridge.js`；**不得新增或改名 IPC 命令 / 事件**，除非同步更新 `src-tauri/src/lib.rs` 与 `capabilities/default.json`。
- 面板为只读展示 + 动作触发：不得在面板内直接读写文件、访问网络、调用 OpenCode；动作执行期间必须置忙（按钮禁用 + spinner + 结果反馈），失败必须显示原因。
- 详情面板是**右侧常驻分栏**，无遮罩、不 `position: fixed/absolute`、不覆盖列表；**任何窗口宽度都不降级为上下堆叠**（`src/` 内现存的媒体查询只有 `prefers-color-scheme` 与 `prefers-reduced-motion` 两处）。收起详情三条等价路径：`Esc`、详情头部「收起详情」按钮、窗口失焦。
- 侧栏为分组导航（模型 / 运行 / 集成 / 其他 + 底部「运行设置」），**5 个入口都是已实现视图**（模型与服务 `/ 运行日志 / 用量与额度 / WorkBuddy 集成 / 关于与更新`），视图由 `src/App.vue` 的 `view` 持有、按当前视图高亮并带 `aria-current="page"`；**禁止**再出现「规划中」标签、禁用占位或可点击却无响应的假入口。
- 新增视图必须遵守只读边界：`read_log` 只读日志尾部、`usage` 只读快照字段、集成视图唯一动作是复用既有 `import`；不得在视图内新增写文件或联网行为。
- 尺寸与颜色一律取自 `src/styles/variables.css`（小字号说明文字用 `--muted-strong`，普通次要文字用 `--muted`），不得在组件里写死颜色或宽度。

| 布局常量 | 值 | 位置 |
|---|---|---|
| 默认窗口 | `1120 × 720` | `src-tauri/tauri.conf.json` → `app.windows[0]` |
| 最小窗口 | `860 × 560`（`minWidth` / `minHeight`） | 同上 |
| 侧栏宽 | `--sidebar-w: 208px` | `src/styles/variables.css` |
| 详情栏宽 | `--details-w: clamp(300px, 45%, 360px)` | 同上 |
| 宽度断点 | **无**（不按窗口宽度堆叠） | `src/` 内无宽度媒体查询 |

### 命名规范

| 类别 | 规则 | 示例 |
|---|---|---|
| Rust 文件 / 模块 | snake_case | `workbuddy_config.rs`、`model_status.rs` |
| Rust 函数 / 变量 | snake_case，动词开头 | `usable_models()`、`sync_published()`、`resolve_models_file()` |
| Rust 常量 | SCREAMING_SNAKE_CASE | `PROBE_TIMEOUT_MS`、`TRANSLATOR_ORDER`、`MAX_BODY_BYTES`、`OWNER` |
| Rust 类型 | CamelCase | `BridgeError`、`PreparedRequest`、`SyncOptions` |
| 对外契约 | 保持 JS 侧原名（snake_case 化） | 路由 `/v1/chat/completions`、`/admin/system-proxy`；错误码 `invalid_model_output` |
| Vue 组件文件 | PascalCase；视图放 `src/views/`，通用组件放 `src/components/` | `views/SideBar.vue`、`components/ModelRow.vue` |

## Git 提交规范

提交格式：`type(scope): content`

| type | 说明 | | scope | 范围 |
|---|---|---|---|---|
| `feat` | 新功能 | | `core` | `src-tauri/core/` |
| `fix` | 修复 | | `ui` | `src/` 面板与 Vite |
| `docs` | 文档 | | `tauri` | 壳与 `src-tauri/icons/` |
| `style` | 格式调整（不影响逻辑） | | `scripts` | 版本脚本 |
| `refactor` | 重构 | | `docs` | 文档 |
| `perf` | 性能优化 | | `ci` | 工作流 |
| `test` | 测试 | | | |
| `chore` | 构建 / 工具 / 依赖 | | | |

示例：`refactor(core): 移除 Node sidecar，核心改为 Rust 内嵌`

提交纪律：

- 提交前必须运行 `cargo test`（`src-tauri/core/`）；测试失败禁止提交。
- 一次提交只包含一类改动，禁止把源码改动与大批二进制 / 图标混在一起。
- **严禁提交**：`api-key`、`.env.local`、`status.json`、`settings.json`、`node_modules/`、`dist/`、`src-tauri/target/`、`src-tauri/core/target/`、`src-tauri/gen/`、`.zwork/`、任何私钥文件，以及仓库外的 Node 归档目录。
- 仓库现状：分支 `dev`，远端 `origin = https://github.com/trexwb/wbBridge.git`（另有 `main`）。历史上只有 `README.md` 被跟踪，**其余文件多处于未跟踪 / 修改态**；提交前务必 `git status` 复核实际纳入内容。
- Agent 完成改动后**不得自动执行** `git commit` / `git push`，除非用户在本轮明确要求。

## 变更与交付约定

1. **改动前**：读取目标文件原文；涉及 `orchestration.rs` 编排、`server.rs` 路由、`protocol.rs` 校验、`runtime.rs` 下载的逻辑，必须同时阅读相关测试（含 `tests/fixtures/*.json` 的快照断言）确认既有行为边界。
2. **改动中**：一次只改一个独立区块 / 函数，避免大范围替换；不修改与任务无关的文件。
3. **改动后**：运行 `cargo test` 与 `cargo clippy --all-targets` 并给出**真实的**通过 / 失败与 warning 数量；用 `grep` / `read` 验证改动已落盘；若改动涉及对外契约（路由、错误码、`status.json` 字段、`models.json` 写入格式、IPC 命令 / 事件），必须在回复中显式列出影响面；若触及红线，同步更新 `tests/red_lines.rs`。
4. **遇到不确定**：宁可询问，也不要凭推测修改安全、供应链、隔离相关代码。
5. **文档类改动不推进版本号**（见[版本与发布](版本与发布)）。
