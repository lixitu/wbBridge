# 已知限制与未验证项

本页是本 wiki 的**诚实边界页**。以下内容区分两类：**未验证项**（可能已实现但缺少实测证据）与**已知限制**（明确的、设计上或实现上的边界）。所有条目均来自 `README.md`、`AGENTS.md`、`docs/validation.md`，不做推测。

## 一、未验证项

> 判定口径：以下能力**没有实机 / 实跑证据**，其状态只能以「编译通过 + 独立核心运行行为」或「静态校验」为证据。相关说明中**不得**把它们描述为已验证。

| # | 项 | 现状 | 现有证据 |
|---|---|---|---|
| 1 | **实际启动 GUI 并操作托盘与面板** | ❌ 从未实机启动（Rust 化后的桌面 GUI） | 仅验证编译、两个 crate 的 clippy 干净，以及独立核心二进制的一次冒烟运行 |
| 2 | **迁移后产出安装包** | ❌ 未产出过 | 无 |
| 3 | **`.github/workflows/release.yml` 在 CI 跑通** | ❌ 从未实际运行 | 仅本地 YAML 结构校验 |
| 4 | **代码签名 / 公证** | ❌ 未执行 | macOS 为 ad-hoc 签名；Windows 未签名 |
| 5 | **Windows / Linux 实机验证** | ❌ 未验证 | Windows ARM64 与 Linux 包由 CI 构建（而 CI 本身未跑通） |
| 6 | **自动更新（updater）** | ❌ 未接线 | `tauri.conf.json` 无 `bundle.createUpdaterArtifacts`，无 `plugins.updater` / `tauri-plugin-updater` 依赖；产物不含 `.sig` 与 `latest.json` |
| 7 | **面板交互的 Tauri 实机验证** | ⚠️ 部分 | 面板布局改造在**浏览器引擎内经 CDP 实测**（非 Tauri GUI 实机）；新增 4 个视图与 `read_log` / `usage` 仅经单测、lint 与构建验证 |

## 二、已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | **免费模型名单、额度与可用性由上游决定** | 本应用不控制也不缓存额度；模型可能随时增减或不可用 |
| 2 | **未做商用代码签名 / 公证** | Windows 可能提示未知发布者；macOS 需按放行说明操作（ad-hoc 签名） |
| 3 | **Windows ARM64 与 Linux 包未实机验证** | 由 CI 构建（且 CI 未跑通） |
| 4 | **仅 PAC / SOCKS 代理暂不支持** | 系统代理仅支持 macOS `scutil` / Windows 注册表解析出的手动 HTTP/HTTPS 代理（与原版一致） |
| 5 | **4 个新视图未经 GUI 实机验证** | 侧栏「运行日志 / 用量与额度 / WorkBuddy 集成 / 关于与更新」已实现（含壳命令 `read_log` 与核心 `usage` 计数），但仅经单测 / lint / 构建验证，**从未在 Tauri GUI 中实机点击确认** |
| 6 | **浅色主题 3 处对比度未达标** | 副标题、页脚说明、耗时行仍用 `--muted`，对比度低于 WCAG AA 的 4.5:1（既有问题，尚未处理） |
| 7 | **`cargo fmt --check` 全仓不干净** | **未作为门禁**；代码风格以 clippy 0 warning 为准 |
| 8 | **探测会消耗少量免费额度** | 免费模型检测向每个模型发送简短真实请求 |
| 9 | **单实例锁约束** | `service.pid` 指示进程存活时重复启动会失败（独立进程退出码 2），不会抢占端口 |
| 10 | **版本号值域说明** | 产品版本 1.0.0；核心 crate 内部版本 0.1.0（有意解耦）；`status.json` 中的 `version` 为历史沿革值 0.2.0（界面上可见），三者**不得**混为一谈 |
| 11 | **仓库提交状态** | 分支 `dev`，历史上只有 `README.md` 被跟踪，其余文件多处于未跟踪 / 修改态；Agent 不得自动 `git commit` / `git push` |
| 12 | **Node 仅用于前端构建** | Node.js >= 24 **只**服务 Vite 构建与 `scripts/*.mjs`；核心运行不依赖 Node，也不得把 Node 运行期重新引入核心链路 |

## 三、不该被描述为"已实现"的事

为避免文档与界面口径失真，以下内容**严禁**在其他页面或对外说明中被当作已完成功能：

- ❌ 宣称 4 个新视图（运行日志 / 用量与额度 / WorkBuddy 集成 / 关于与更新）已经 GUI 实机验证，或宣称「关于与更新」已接入自动更新；
- ❌ 宣称 GUI / 托盘 / 窗口行为已实机验证；
- ❌ 宣称已产出安装包或 CI 已跑通；
- ❌ 宣称自动更新可用，或引导用户生成签名私钥；
- ❌ 把 `status.json` 中的 `0.2.0` 当作产品版本；
- ❌ 宣称已支持 PAC / SOCKS 代理。

## 四、如何把这些边界用起来

- 提交 / 发布前，请对照[版本与发布](版本与发布)的「发布前检查清单」，其中「实机启动 GUI」「产出安装包」两项目前**尚未完成**。
- 排查问题时，先确认自己处在哪种运行形态（见[常见问题与故障排查](常见问题与故障排查)）。
- 若在新环境中完成了上述任一未验证项，应在 `docs/validation.md` 追加记录，并同步更新本页与 `README.md`。
