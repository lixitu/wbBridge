# 已知限制与未验证项

本页是本 wiki 的**诚实边界页**。以下内容区分两类：**未验证项**（可能已实现但缺少实测证据）与**已知限制**（明确的、设计上或实现上的边界）。所有条目均来自 `README.md`、`AGENTS.md`、`docs/validation.md`，不做推测。

## 二、已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | **免费模型名单、额度与可用性由上游决定** | 本应用不控制也不缓存额度；模型可能随时增减或不可用 |
| 2 | **未做商用代码签名 / 公证** | Windows 可能提示未知发布者；macOS 需按放行说明操作（ad-hoc 签名） |
| 3 | **Windows ARM64 与 Linux 包未实机验证** | 由 CI 构建（且 CI 未跑通） |
| 4 | **仅 PAC / SOCKS 代理暂不支持** | 系统代理仅支持 macOS `scutil` / Windows 注册表解析出的手动 HTTP/HTTPS 代理（与原版一致） |
| 5 | **4 个新视图未经 GUI 实机验证** | 侧栏「运行日志 / 用量与额度 / WorkBuddy 集成 / 关于与更新」已实现（含壳命令 `read_log` 与核心 `usage` 计数），但仅经单测 / lint / 构建验证，**从未在 Tauri GUI 中实机点击确认** |
| 6 | **浅色主题 3 处对比度未达标** | 副标题、页脚说明、耗时行仍用 `--muted`，对比度低于 WCAG AA 的 4.5:1（既有问题，尚未处理） |
| 7 | **`cargo fmt --check` 全仓不干净** | **未作为门禁**；代码风格以 clippy 0 warning 为准 |
| 8 | **探测会消耗少量免费额度** | 免费模型检测向每个模型发送简短真实请求 |
| 9 | **单实例锁约束** | `service.pid` 指示进程存活时重复启动会失败（独立进程退出码 2），不会抢占端口 |
| 10 | **版本号值域说明** | 产品版本 1.0.2；核心 crate 内部版本 0.1.0（有意解耦）；`status.json` 中的 `version` 为历史沿革值 0.2.0（界面上可见），三者**不得**混为一谈 |
| 11 | **仓库提交状态** | 分支 `dev`（远端 `origin = https://github.com/trexwb/wbBridge.git`，另有 `main`），`git ls-files` 有 **103** 个被跟踪文件；v1.0.2 的版本推进与本轮改动**仍在工作区未提交**（提交由用户决定，Agent 不自动 `git commit` / `git push` / `git tag`） |
| 12 | **Node 仅用于前端构建** | Node.js >= 24 **只**服务 Vite 构建与 `scripts/*.mjs`；核心运行不依赖 Node，也不得把 Node 运行期重新引入核心链路 |
| 13 | **v1.0.1 及更早的用户收不到自动更新** | 那一版根本没接线 updater（产物无 `.sig`、面板无更新区），必须由用户手动下载安装包升级一次；从 v1.0.2 → v1.0.3 起更新链路才可能自我生效 |
| 14 | **更新通道受 Draft 闸门控制** | endpoint 指向 `releases/latest/download/latest.json`，而 GitHub 的 `releases/latest` **不含 draft 与 prerelease**——人工点「Publish release」之前，老客户端拿到 404 属预期（draft 即灰度闸门），不是"更新功能坏了" |
| 15 | **面板偏好只持久化两项** | 当前视图、以及「启动后自动检查更新」开关（`src/core/prefs.js`，键前缀 `wb.` + 字段白名单 + 2KB 上限）。详情栏收起状态与窗口尺寸/位置**不持久化**：后者需要 `tauri-plugin-window-state`（新依赖 + 与 `quit_app` 关停时序的交互无法在无 GUI 验证下确认，故未接入）。**注意别混淆**：系统代理开关与 WorkBuddy 配置文件路径由**核心**持久化在数据目录 `settings.json`，与面板 `localStorage` 无关 |
| 16 | **存储里绝不写凭据** | `prefs.js` 的写入路径只接受白名单键、且对值做字段投影（如 `update` 只留 `autoCheck` / `lastCheckedAt`）；`api-key`、`OPENCODE_SERVER_PASSWORD`、models 文件路径等一律进不了 `localStorage`（有对应单测钉住） |

## 三、不该被描述为"已实现"的事

为避免文档与界面口径失真，以下内容**严禁**在其他页面或对外说明中被当作已完成功能：

- ❌ 宣称 4 个新视图（运行日志 / 用量与额度 / WorkBuddy 集成 / 关于与更新）与更新区已经 GUI 实机验证；
- ❌ 宣称 GUI / 托盘 / 窗口行为已实机验证；
- ❌ 宣称 CI 已跑通，或宣称除 **macOS aarch64 dmg** 之外的平台安装包已产出；
- ❌ 宣称「自动更新已端到端可用」（真实的一次 检查→下载→安装→重启 尚未做过），或引导用户自行生成签名私钥（wbBridge 专用钥已由维护者生成并内嵌公钥，换钥必须同步换 `pubkey`）；
- ❌ 把 `status.json` 中的 `0.2.0` 当作产品版本；
- ❌ 宣称已支持 PAC / SOCKS 代理；
- ❌ 宣称接入了商业代码签名或 Apple 公证（A7 只是把**接入位置与所需变量**写进文档，配置里没有这些键）；
- ❌ 宣称「更新失败后的一次真实回滚」已走过，或宣称 `localStorage` 偏好已在真实 WebView 里验证过。

## 四、如何把这些边界用起来

- 提交 / 发布前，请对照[版本与发布](版本与发布)的「发布前检查清单」，其中「实机启动 GUI」仍未完成，「产出安装包」目前只有 macOS aarch64 的 dmg 落地（其余五平台待 CI），且**推标签之前必须先确认 GitHub Secrets 已配好签名私钥**、并遵守「先版本推进提交、再在该提交上打标签」的顺序。
- 排查问题时，先确认自己处在哪种运行形态（见[常见问题与故障排查](常见问题与故障排查)）。
- 若在新环境中完成了上述任一未验证项，应在 `docs/validation.md` 追加记录，并同步更新本页与 `README.md`。
