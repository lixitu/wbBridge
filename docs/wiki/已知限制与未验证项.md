## 三、不该被描述为"已实现"的事

为避免文档与界面口径失真，以下内容**严禁**在其他页面或对外说明中被当作已完成功能：

- ⚠️ 4 个新视图（运行日志 / 用量与额度 / WorkBuddy 集成 / 关于与更新）与更新区**现已随 GUI 实机运行**（2026-10-11 取证：app 已安装运行、`status.json` 持续更新）；但逐视图版式 / 对比度 / 交互的系统性核验仍属计划 R-05，**尚未逐视图走查**，不得宣称「版式已核验达标」；
- ⚠️ GUI / 托盘 / 窗口行为**现已实机运行**（2026-10-11 取证）；但关窗即退出、托盘驻留取消、macOS 红按钮语义等具体手感属 R-05 核验范围，**尚未逐项目点过**；
- ❌ 宣称除 **macOS aarch64 dmg** 之外的平台安装包只停在"待 CI 产出"（2026-10-03、2026-10-10 两轮 CI 都把六平台产物 + `.sig` + 清单各发了一次，随 Release `v1.0.2` / `v1.1.10` / `v1.1.15`）；`latest.json` 现在**可以**说「已下发且六条资产 url 实测 200」（`v1.1.15` 清单，`v1.0.2` 那轮的六条 url 曾因 GitHub 把资产名空格规范化成 `.` 全部 404，脚本与 CI 对账步骤已修并在那一轮实跑通过），**但仍不得据此宣称更新链路端到端可用**——客户端验签、下载安装、`relaunch()` 带新核心起来都没走过；
- ❌ 宣称「自动更新已端到端可用」（真实的一次 检查→下载→安装→重启 尚未做过），或引导用户自行生成签名私钥（wbBridge 专用钥已由维护者生成并内嵌公钥，换钥必须同步换 `pubkey`，且只有 `pubkey` 第一条生效）；同样不得把"产出了 `.sig`、CI 全绿"当成客户端验签通过——`with-updater-key.mjs` 是 `npm run tauri:build` 的**注入包装器**（不判形态、不试签、配对不符只告警），本地产出 `.sig` 只证明**钥 + 口令能用、key ID 与配置一致**，不证明产物已被客户端验签；
- ❌ 把 `status.json` 中的 `0.2.0` 当作产品版本；
- ❌ 宣称已支持 PAC / SOCKS 代理；
- ❌ 宣称接入了商业代码签名或 Apple 公证（A7 只是把**接入位置与所需变量**写进文档，配置里没有这些键）；

- ❌ 宣称 Windows 的「反复退出码 2」已定位或已修复（**未取证、未修**，本页与故障排查给出的都只是临时恢复步骤；按 1s 探 `/health` 区分「确有实例 / 残锁」的方案只是计划）；
- ❌ 宣称「同步失败还能自动回滚到上一份配置」（当前版本**完全不写备份**，兜底只有原子替换 + 文件锁 + 写前二次读取），或宣称补建出来的空 `models.json` 已被插件自身成功读入；

## 四、如何把这些边界用起来

- 提交 / 发布前，请对照[版本与发布](版本与发布)的「发布前检查清单」，其中「实机启动 GUI」**已于 2026-10-11 取证完成**（`/Applications/WB Bridge.app` 1.1.15 已安装运行），「产出安装包」本机 macOS aarch64 的 dmg 落地、且 app 已实机安装运行；其余五平台已由 2026-10-03 / 2026-10-10 / 2026-10-11 三轮 CI 完整跑完，分别随 Release `v1.0.2` / `v1.1.10` / `v1.1.15` 各发布过一次 23 资产（**Windows / Linux 包仍待实机安装核验**，见条目 5），且**推标签之前必须先确认 GitHub 仓库级 Variables 已配好签名私钥全文与非空口令**（缺任一项会在一整套 Rust 编译跑完后的打包那一步报 `Missing comment in secret key`，2026-10-03 首轮 CI 正是栽在这里）。CI 与本地都**没有**私钥前置校验这一步：构建直接走 `npm run tauri:build` / `npm run build`，包装器只注入私钥（不判形态、不试签、配对不符只告警），所以要人工核对它打印的来源与 `.sig` 的 key ID 是否等于 `plugins.updater.pubkey` 里那条；同时遵守「先版本推进提交、再在该提交上打标签」的顺序。
- 排查问题时，先确认自己处在哪种运行形态（见[常见问题与故障排查](常见问题与故障排查)）。
- 若在新环境中完成了上述任一未验证项，应在 `docs/validation.md` 追加记录，并同步更新本页与 `README.md`。
