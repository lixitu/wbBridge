# 使用指南

本页说明控制面板的界面分区与交互、模型状态与徽章含义、系统代理开关，以及窗口关闭与退出行为。文案与行为均取自当前面板源码（`src/App.vue`、`src/views/*.vue`、`src/components/ModelRow.vue`、`src/core/activity.js`）与壳源码（`src-tauri/src/lib.rs`）。

> 界面本身**已于 2026-10-11 实机运行取证**（`/Applications/WB Bridge.app` 1.1.15 已安装并运行）；但逐视图版式 / 对比度核验（计划 R-05）仍待实机逐一点过，布局改造最初是在浏览器引擎内实测的，细节仍可能与实际呈现存在出入，详见[已知限制与未验证项](已知限制与未验证项)。

| 底部说明 | 「基于 Tauri + Vue · <版本号>」与「模型名单与免费额度由上游决定」 |

**6 个入口都是已实现视图**（视图状态由 `src/App.vue` 的 `view` 持有；点击切换，当前视图在侧栏高亮并带 `aria-current="page"`）：

| 视图 | 组件 | 内容与数据来源 |
|---|---|---|
| **模型与服务** | `src/App.vue`（`.top` + `.content`） | 主从两栏：模型列表 + 右侧常驻详情（见 §2.2、§4） |
| **平台** | `src/views/ProvidersView.vue` | 四家平台卡片（静态注册表驱动，恒常显示，含「已配置 / 未配置」徽章）；password 型输入框保存 Key，**保存后立即清空、明文与掩码都不回显**；保存 / 清除后**自动应用**：先**重启隔离的模型子进程**以载入新 Key（不动应用窗口），再**只重新获取、重新检测这一家**，其余平台的目录与结果原样保留；自动应用失败时可点「读取免费模型（重新应用）」重试全量读取（保存 / 清除 / 重新应用三者互斥，忙态按钮显示「应用中」）；内置官方申请页直达（经壳 `open_external` 用系统浏览器打开，仅 https） |
| **运行日志** | `src/views/LogsView.vue` | 经壳命令 `read_log` 只读拉取数据目录 `opencode.log` 的**尾部**（带「刷新」按钮与截断提示） |
| **用量与额度** | `src/views/UsageView.vue` | 渲染 `status.json` 顶层 `usage`：累计请求总数 + 逐模型表（请求 / 成功 / 失败 / 最近用时 / 平均用时） |
| **插件集成** | `src/views/IntegrationView.vue` | 只读展示两个目标的配置定位与最近一次发布结果；唯一动作是复用既有的**导入**（`import`） |
| **关于与更新** | `src/views/AboutView.vue` | 版本、数据目录（`data_dir_path`）与状态字段 + **自动更新区**：启动约 5 秒后静默检查一次，发现新版本才显示更新条与「下载并安装」，装完由用户点「重启应用」生效 |

- 侧栏不存在「规划中」标签或禁用占位，点击任一入口即切换主区；切换视图**不重置**已选模型与面板状态。
- 除「模型与服务」与「平台」外的 4 个视图都是**只读展示**：不写文件、不访问 OpenCode。「平台」视图是**唯一写凭据的入口**（Key 只经 `POST /admin/set-provider-key` 的请求体进入核心，落 `providers.json`）；其余写动作仍是既有的 `import`。**唯一联网入口是自动更新**（「关于与更新」视图）：面板只调 Tauri 官方 updater/process 插件命令，真正的下载由 **Rust 侧**发起，不经 WebView `fetch`，因此 CSP 的 `default-src 'self'` 无需放宽。
- 「用量与额度」的数字是**核心累计真实请求**（只统计 `source == "request"`，探测不计、连接断开的取消不计入），跨核心重启延续。

## 3. 交互

### 3.1 选中与收起详情

- 点击模型行即选中，详情在**右侧常驻分栏**显示；再次点击同一行取消选中。
- 键盘：列表为 `role="listbox"`，`↑` / `↓` 在列表内移动焦点**并同时选中**该模型（详情随之更新）；`Enter` / `Space` 沿用按钮原生行为。
- 收起详情有**三条等价路径**：按 `Esc`、点详情头部右上角的「收起」按钮（`aria-label="收起详情"`，提示「收起详情（Esc）」）、窗口失焦（`onDismiss`）。
- 收起即清空选中，列表立刻占满主区宽度。详情是右侧分栏而**不是浮层**：无遮罩、不覆盖列表、不随窗口宽度改为上下堆叠。

### 3.2 动作执行时的置忙与反馈

所有动作在执行期间统一置忙：按钮禁用 + spinner，同一时刻只允许一个动作（重复触发会返回「已有操作进行中」）。失败时错误信息进反馈条，且**不能用未经核实的推测替代错误原文**。

| 动作 | 触发位置 | 说明 |
|---|---|---|
| `refresh` | 「读取免费模型」 | 重新读取免费模型目录（含重启运行时） |
| `probe` | 「检测全部」 | 不传 model 即探测全部 |
| `probe` | 不可用模型行内的「**重新检测**」 | 载荷 `{ model: <客户端 id> }`；点击后按钮留在原位转为「检测中」（spinner + `aria-busy` + 禁点），可与整批探测**并发**——忙态来自核心顶层 `singleProbes` 与面板本地已点击集合的并集，因此不可能卡死 |
| `probe` | 「平台」视图保存 / 清除 Key 之后 | 载荷 `{ providers: [<平台 id>] }`：**只重取并重检这一家**，其余平台的目录与探测结果一概不动。形态不对（非数组 / 空数组 / 未注册 id / 与 `model` 同时给）当场拒绝，绝不静默降级成全量 |
| `import` | 「导入 WorkBuddy / CodeBuddy」 | 弹出系统文件选择器选择 `models.json`；写入**所有**已检测到的插件目标 |
| `system-proxy` | 侧栏开关 | 载荷 `{ enabled: boolean }` |
| `restart` | 服务状态行的「重试」 | **不经** `/admin/*`，直接映射为壳命令 `restart_core` |
| `read_log`（只读） | 日志页的「刷新」 | **不经** `/admin/*`，直接调用壳命令 `read_log` 拉取日志尾部；无参数、不写文件 |
| `open_external`（只读） | 「平台」视图的官方申请页 | **不经** `/admin/*`，用系统浏览器打开 https 外链（WebView 里 `target=_blank` 默认静默失败）；仅 https + 字符白名单 |

按钮的禁用条件：任一动作进行中、检测进行中（`probe.running`）、或服务阶段不是 `ready`（`restart` 例外，服务处于 `error` 时才出现）。此外由 `src/core/ops.js` 统一守卫：**在飞互斥**（同一动作重复触发被拒并提示，文案逐字稳定所以连点不闪烁）、**完成冷却**（终态动作 refresh / restart / system-proxy / import 成功后 5 秒内重复触发提示「刚完成」，失败不进冷却）、**成功文案 5 秒自动消隐**（失败文案不消隐）；被拒绝的开关必须回弹视觉状态。

### 3.3 列表排序与空态

列表按「可用在前 → 检测中 / 待检测 → 不可用（探测明确失败）在后」排序，同档内按模型名排序。列表为空时显示占位文案「正在安装或扫描模型，完成后将在这里显示。」

### 3.4 无障碍与主题

- 服务状态行、反馈条均带 `role="status"` + `aria-live` 播报。
- 导航项带 `title` 与 `aria-current`，开关带 `aria-checked`，详情按钮带 `aria-label`。
- 主题跟随系统深浅色（`prefers-color-scheme`），并响应 `prefers-reduced-motion`；这两种媒体查询是面板内**仅有的**宽度无关适配，**不存在**按窗口宽度堆叠的媒体查询。

## 4. 模型状态与徽章含义

每个模型行展示三样东西：模型名、耗时行、右侧徽章组。

> ⚠ 模型名这一列渲染的是 `status.json` 里该模型对象的 `id`，也就是**内部全限定 id**（`<命名空间>/<目录 key>`，如 `opencode/big-pickle`、`modelscope/MiniMax/MiniMax-M1-80k`），**不是**客户端可见的那个展示 ID。展示 ID 由 `model_status.rs::client_model_id` 现算，只在 `/v1/models`、WorkBuddy / CodeBuddy 的配置与用量统计里出现，形态是 `<前缀> · <名称>`：注册表平台用其 `label`（`ModelScope · …` / `智谱 · …` / `腾讯混元 TokenHub · …` / `SiliconFlow · …`），`opencode` 与未注册命名空间一律回落历史前缀 `OC`（单测 `model_status.rs::client_prefix_follows_the_namespace_but_never_renames_opencode` 把这条逐形态钉死）。若要让模型行直接显示展示 ID，那是一次代码改动，不是文档措辞问题。

### 4.1 能力徽章

| 徽章 | 出现条件 | 含义 |
|---|---|---|
| **推理** | 模型声明了 `reasoning` | 支持推理档位；详情中会列出可选档位 |
| **图片** | 模型声明了 `images` | 支持图片输入 |

### 4.2 状态徽章

状态徽章的判定顺序如下（自上而下优先）：

| 徽章文案 | 出现条件 | 含义 |
|---|---|---|
| **检测中** | 该模型正在被检测（同时处于等待队列且是当前探测对象） | 正在发送探测请求 |
| **等待检测** | 在检测队列中但尚未轮到 | 排队等待 |
| **请求中** | 有正在进行的真实调用（活动流里有该模型） | 有 WorkBuddy 请求在途 |
| **可用** | 在发布集内且非纯文本模型 | 探测通过，已可供 WorkBuddy 使用 |
| **可用 · 仅对话** | 在发布集内且 `chatOnly` | 探测通过，但已自动关闭工具调用，仅支持普通对话 |
| **检测超时** | 类别 `timeout` | 探测/调用超时 |
| **额度不足** | 类别 `quota` | 上游额度不足 |
| **请求受限** | 类别 `rate_limit` | 被上游限流 |
| **访问受限** | 类别 `access` | 无权限访问该模型 |
| **不可用** | 探测明确失败（`ok === false`）但无上述类别 | 通用不可用 |
| **待检测** | 以上都不满足 | 尚未检测或结果未知 |

### 4.3 耗时行

- 有耗时数据时显示：`最近检测 · 响应耗时 <X>` 或 `最近检测 · 失败耗时 <X>`（调用来源则显示「最近调用」）；小于 1 秒用毫秒，否则用「N.N 秒」。
- 无耗时数据时显示 `响应耗时 —`。

> 口径说明（页脚亦会提示）：**耗时是完整请求用时，不是首字延迟**；不可用模型仅在本窗口保留，不供 WorkBuddy 使用；剩余额度暂不可查询。

### 4.4 详情栏

详情头部显示模型的**完整 ID**（等宽字体），正文逐行给出：

- 若为纯文本模型：`已自动关闭工具调用；导入后仅支持普通对话。`
- 若最近一次调用拦截过本地执行尝试：`最近一次调用拦截了 N 次本地执行尝试，动作必须由 WorkBuddy 执行。`（告警色）
- 若最近一次调用返回了动作：`最近一次调用返回了 N 个动作。`
- 若发生过工具交接：`最近一次调用把被拦下的本地动作转交成外部 <N> 调用。`
- 若发生过格式兜底：`这一轮由格式兜底救回：动作转写（模型名）、信封重排（模型名）。`
- `图片输入：支持 / 不支持`
- `上下文：… · 输入上限：… · 输出上限：…`（未声明时显示「未声明」）
- `推理：支持 · 可选档位：<a / b / …>` 或 `推理：OpenCode 未声明支持`
- 若有错误：原文错误信息（告警色）
- `最近更新：<本地时间>` 或 `最近更新：尚未检测`

详情正文可选中复制（`user-select: text`）。

## 5. 系统代理

- 开关位置：侧栏底部「运行设置 → 使用系统代理」。
- 打开后，运行时下载与模型请求都会走**系统 HTTP/HTTPS 代理**：核心在 macOS 上读 `scutil --proxy`、Windows 上读注册表，解析结果注入 OpenCode 子进程的环境变量。
- **解析失败会回退为关闭，不阻断启动**（因此开关可能自行弹回关闭态）。
- 解析或注入失败时会有可见反馈——不会静默失败。
- 已知限制：**PAC / SOCKS 代理暂不支持**（与上游实现一致）。
- 托盘菜单里也有一项「使用系统代理」，与面板开关是同一个设置。

## 6. 页脚提示

页脚有两行内容：

1. **同步状态行**，三种形态：
   - 发生错误时显示错误原因；
   - 已导入过：`已导入 <N> 个模型 · 再次检测后需点击导入 WorkBuddy 更新`；
   - 尚未导入：`首次读取和检测完成后自动导入 WorkBuddy`。
2. **说明行**（原文）：启动后自动发送简短请求检测，会使用少量免费额度，不代表工具流程已验证。耗时为完整请求用时，非首字延迟。不可用模型仅在本窗口保留，不供 WorkBuddy 使用；剩余额度暂不可查询。

另需注意：**再次检测完成后不会自动写入 WorkBuddy**，需要再点一次「导入 WorkBuddy」。

## 7. 窗口关闭与退出

**关闭窗口 = 退出整个应用**（macOS / Windows / Linux 一致）。壳在 `CloseRequested` 里先隐藏窗口、随后在后台线程走完与托盘「退出」完全相同的关停链路：停止核心（含 WorkBuddy 配置清理）→ 结束进程。因此**不存在「窗口关了但服务还在后台跑」的状态**，也不需要用户再去托盘点一次退出。

> 关停最坏数秒（预算见下）。这段时间窗口已隐藏、进程仍在收尾；托盘左键「打开控制面板」在退出流程中不会再唤回窗口（`show_main` 见 `quitting` 即返回）。

托盘菜单共四项（`src-tauri/src/lib.rs::build_tray`）：

| 菜单项 | 行为 |
|---|---|
| 打开控制面板 | 显示窗口、取消最小化并聚焦（退出流程中不再唤回） |
| 使用系统代理 | 勾选式开关，与面板开关同源 |
| 选择 WorkBuddy 配置… | 重新指定 `models.json` 路径 |
| 退出 WB Bridge | 优雅退出（见下） |

托盘的**左键单击**也会打开控制面板（菜单改为右键/显式点击弹出）。

### 退出流程

无论从窗口关闭按钮还是托盘「退出 WB Bridge」退出，壳都按同一固定预算做优雅关停：

1. 记录「正在退出」状态，标记所有窗口关闭请求不再拦截；
2. 向核心发 `/admin/shutdown`（先响应、再触发一次优雅退出）；
3. 等待核心退出回调，超时预算 **8 秒**（`STOP_BUDGET = 8s`）；超时则交由核心的父进程监护自行退出（`BUDDY_PARENT_PID` 看门狗）；
4. 核心会先完成 **WorkBuddy 配置清理**（移除自己名下的条目、保留用户其他配置）再收尾；
5. 壳保存设置、结束进程。

> 核心**不会也不能**单方面结束壳进程：嵌入壳时，核心的「退出」被翻译为记录退出码与停止状态，真正的进程退出只由壳的关窗 / 托盘退出 / `RunEvent::ExitRequested` 驱动。独立运行核心二进制时，`BUDDY_PARENT_PID` 看门狗会在父进程消失后自动优雅退出，不留占端口的孤儿进程。
