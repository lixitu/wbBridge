## 本版主题

**一、平台 Key 接入从「能注入」变成「真能用到模型」。** 侧栏「平台」视图填入自己持有的 Key 后，ModelScope（魔搭）、SiliconFlow（硅基流动）、腾讯混元 TokenHub、智谱 四家的免费模型会和 OpenCode 自带的免费模型一起被发现、探测并发布给 WorkBuddy / CodeBuddy。其中 **ModelScope 的清单改为按对方推理网关实际在册的模型逐条声明**——此前按上游目录（models.dev）的声明走，两边交集为空，该平台全部模型都以一句 `has no provider supported` 失败（本版把它改成了看得懂的中文说明，并换成真正能调的 9 个条目）。

**二、一批真实使用中暴露的问题被修掉**：上游英文报错看不懂（地区拒绝、模型已撤架、不支持函数调用、提供方未承接、服务 id 不在册、这把 Key 没开通）；改一家 Key 却把四个平台全部重读重检、按整份目录烧探测额度；重启应用后要重新等一轮全量探测；插件配置目录里按发布次数堆积几十个从没人读的 `.bak`；装了插件但从未保存过自定义模型时**永远检测不到目标**；`opencode --version` 回读偶发卡住后一次性失败。

不填任何平台 Key 时，本版行为与 v1.1.0 一致（OpenCode 自带的 `OC · ` 模型照常发现、探测、发布）。

## 新增功能

### 1. 面板「平台」视图

- 侧栏「模型」组新增入口，四家平台卡片**恒常显示**（静态清单驱动，不依赖核心在线；状态请求失败时卡片不会整页消失），含「已配置 / 未配置」徽章；
- Key 输入框为密码型，**保存后立即清空**——面板不留任何副本，明文与掩码都不回显；
- **保存 / 清除后自动热生效，且只针对这一家**：自动触发该平台的重新读取与重新探测，其余平台的目录与探测结果一概不动（只重启隔离的模型子进程，应用窗口与本地 HTTP 服务不动）；底部「读取免费模型（重新应用）」为兜底手动入口，自动应用失败（如网络抖动）时可重试；
- 每张卡片内置「申请 Key（三步）」指引与官方申请页直达按钮（经壳的 `open_external` 命令用**系统浏览器**打开——Tauri WebView 里 `target=_blank` 默认静默失败，外链必须经壳转发；仅接受 https）；
- 保存 / 清除 / 逐平台应用三个动作互相排斥，忙态在按钮上给「应用中」。

### 2. 多平台模型发现与发布（核心）

- **Key 注入**：启动时从数据目录 `providers.json` 读出已配置平台，以声明段 `{ npm, options: { baseURL, apiKey }, models }` 经 `OPENCODE_CONFIG_CONTENT` 注入隔离子进程；Key 绝不进环境变量白名单、不进日志、不进 `status.json`、不出现在任何响应体；
- **聚合发现**：在既有 `opencode` 命名空间之外逐个已配置平台发现免费模型（CostZero 判定复用：输入/输出/缓存全 0 + 支持文本输出 + 未下线）；**单平台失败不丢其他平台**（失败只记日志）；
- **空发布集闸门**：一轮探测全部失败时拒绝清空插件配置里本工具名下的条目并显式报错（关停 / 启动清旧 / 换配置文件三处「用户意图的清空」不受影响，且退出时的清空只动本工具自己的条目）；
- **展示前缀**：新模型按平台显示，如 `ModelScope · …`、`智谱 · …`（模型行改为直接渲染真实 client id，顺带修掉此前模板硬编码 `OC · ` 的偏差）。

### 3. ModelScope 按对方网关实际在册的清单发布

ModelScope 的免费推理网关与 models.dev 的目录声明**完全不一致**：网关公开可读的 `/v1/models` 在册约 35 个 id，而目录给出的 7 个「免费」id 一个都不在其中——于是每个都以 `Model id : <id> , has no provider supported` 失败。本版起，注册表为 ModelScope 携带一份**手工维护的权威清单**，发现阶段只放行清单里的 id（OpenCode 是把注入段与目录**合并**而非替换，所以光声明不够，必须同时过滤），清单外的过期 id 不再进探测队列。

| 阶段 | 清单条目数 | 说明 |
|---|---|---|
| v1.1.0（目录声明） | 7 | 全部打不通 |
| v1.1.6 ~ v1.1.9（网关实际在册） | 13 | 按「文本生成」类筛选，排除多模态 / 图像生成 / 垂直专用（SQL、评审、医疗）与未声明任务的条目；同能力的新快照不重复收 |
| **v1.1.10** | **9** | 真实 Key 实测后再削掉 4 条「在册但打不通」的：3 个 `PaddlePaddle/ERNIE-4.5-*-PT` 报 HTTP 401「该 Key 没有访问权限」（要先在对方控制台开通），`meituan-longcat/LongCat-Flash-Lite` 报 HTTP 400（网关把它映射到自己也不承接的变体）。留着它们只在面板上常驻红色行并重复烧额度，故直接从清单去掉；对方日后开放了再加回 |

当前在册的 9 条：MiniMax-M1-80k、GLM-4.7-Flash、GLM-5.2、DeepSeek-V4-Flash-0731、DeepSeek-V4-Pro、Mistral-Large-Instruct-2407、Nex-N2.5-Pro、Nex-N2.5-mini、Step-3.5-Flash。

> 🔴 如实说明两点：① 这些条目的 `cost: 0` 是**本工具的主动声明**（免费判定依赖它），依据是对方公开的推广口径「每日提供 2000 次免费 API 调用额度」，**不是**接口回读到的值；② 上下文上限按「实测可用档再低一档」保守声明，输出取上下文的 1/8。SiliconFlow / 腾讯 / 智谱 三家仍信任目录声明（与网基本致），各家免费模型数为 SiliconFlow 3、腾讯 2、智谱 3（2026-10-09 沙箱实测 catalog，随上游变动）。清单随版本发布、不做远程拉取。

### 4. 插件目录已在、但没有 `models.json` 时自动补建

装了 WorkBuddy / CodeBuddy 却从未保存过自定义模型的机器上，数据目录（如 `~/.workbuddy`、`~/.codebuddy`）存在而 `models.json` 不存在，此前一律判「未检测到」——插件装了，模型却永远发布不过去。本版在**默认位置**发现不到配置文件、但目录确实存在时，补建一个空的 `models.json`（内容 `[]`），随后正常发布。

三条边界：文件已存在时**绝不改写**；目录不存在时**不替插件建目录**（目录不在＝没装，不能凭空造出「已安装」的假象）；写不进去（权限、只读盘）则静默跳过，按原样报「未检测到」。用户用环境变量或导入动作**显式指定**的位置不参与补建——那里失效必须照旧报未检测到。

### 5. 操作守卫：每一次点击都有回应

所有触发后台动作的入口统一加上：① 成功文案（5 秒自动消隐，失败文案不消隐）；② 同一动作在飞时重复点击被拒绝并提示（防抖）；③ 终态动作（重新读取 / 重启 / 代理开关 / 导入）成功后 5 秒内重复点击被拒绝并提示「刚完成」（节流，失败不进冷却）；④ 被拒绝的开关必须回弹视觉状态，不停留在假位置。反馈条在除「模型与服务」外的**所有视图**都可见（此前代理开关在平台 / 日志 / 用量 / 关于里失败了没地方显示）。

## 修复与改进

1. **ModelScope 全部模型报 `has no provider supported`**：两步修掉。先是补齐注入形态——对目录在册的 provider，声明段**不带非空 `models` 段**时整条调用链在 ai-sdk 层解析失败；无清单时补一个锚点条目占位（该条目被 OpenCode 合成 cost 全 0 的幽灵模型，按保留名过滤，绝不进发布集），有清单时逐条声明。再换成上一节第 3 条的权威清单。
2. **改一家 Key 只重读重检那一家**：管理接口支持 `{ model?, providers?[] }` 定向范围，其余平台的目录与探测结果一概不动，只有本平台名下的「已校验」标记被摘掉重新探测。请求体形态不对（非数组 / 空数组 / 未注册 id / 与 `model` 同时给）**当场拒绝**，绝不静默降级成全量——后者会按整份目录消耗探测额度（每模型 60s 预算）。
3. **启动沿用上次结果**：应用启动不再清空发布集、不再自动全量重读重检，直接沿用上次的目录与探测通过集重新下发配置（顺带修掉端口漂移与 api-key 轮换后插件里仍是旧地址的问题）。目录非空且至少一个模型通过才沿用；首启、上一轮全败、数据形状不对时完全走老路径。⚠ 代价如实说明：应用没在跑的那段时间，插件里本工具名下的模型指向已停掉的端点，请求会失败。
4. **重新检测全程有过程反馈**：单模型「重新检测」在行内显示 spinner 与「检测中」并禁点，可与整批探测并发（忙态集合独立于批量探测的进度对象，互不覆盖），同一模型重复点击去重，且不可能卡死（本地标记只在请求 ACK 前或失败时存在）。
5. **上游英文报错改成可操作的中文说明**（错误码与 HTTP 状态**逐字保留**，都**不触发重试**、不撤销其它已发布模型；上游原文一并留在说明里便于对账）：
   - `This model is not available in your country` → 说明这是按**出口 IP 的国家/地区**给的拒绝，不是 Key 或本工具的问题，并给出可操作入口；
   - `Model exo-free has been deprecated.` → 说明这是提供方撤架，不会被发布、也不会重复烧额度；
   - `Bad Request: Function call is not supported for this model.` → **不再整个丢弃模型**（见下条）；
   - `Model id : <id> , has no provider supported` → 说明请求已带 Key 打到对方、鉴权也通过，是对方的推理网关没承接这个 id，请改用该平台上明确支持 API 推理的模型；
   - `The model or service ID <id> does not exist.`（腾讯 TokenHub）→ 说明对方在线推理服务列表里没有这个条目，请以控制台在册服务为准；
   - **v1.1.10 新增** `The model does not exist or you do not have access to it.`（ModelScope）→ 说明这个条目**确实在**对方的模型清单里、只是这把 Key 还没被开通授权，下一步是去申请开通而不是换模型。判定刻意分开，且「endpoint is unavailable」这类临时不可用不得被说成权限问题。
6. **「不支持函数调用」改为按仅对话发布**：上游明说该模型不支持函数 / 工具调用时，归入格式类失败，由既有降级通道向它发一次**真实的纯对话请求**，通了就按「仅对话」发布并注记「模型不支持函数调用，已按仅对话发布」（不再回显吓人的原文）；兜底那次对话请求也被**同一理由**拒绝时同样确认仅对话（OpenCode 的 chat-only 通道对该模型仍走工具路由，主探测与兜底指向同一结论）。仅当兜底报的是别的错（鉴权 / 404 / 限流…）才照旧记失败。另：OpenCode 把这句包进 `StructuredOutputError` 时曾被吞成泛化「未返回信封」使降级触发不了，现已放行给降级逻辑。
7. **插件配置目录不再堆积备份**：写盘**不再产生** `models.json.buddy-bridge-<毫秒>.bak`（从来没有读取方、面板也没有恢复入口，却按发布次数无限堆积，几天下来几十个），并在每次同步（**包括内容无变化那一次**）把旧版攒下的同族存量备份清扫掉。判定是逐段白名单——只删本工具自己那一种命名形态，用户自己的 `*.bak`、`*.tmp`、名字不匹配的文件一个都不碰。⚠ 从此插件配置被写坏时**没有自动回滚点**，唯一兜底是「文件锁 + 写前二次读取 + 同目录临时文件再原子替换」本身。
8. **`opencode --version` 回读超时改为重试一次 + 中文说明**：启动隔离服务前的第一次版本回读（15s 预算）偶发卡住时不再一次性失败，超时后重试一次；两次都超时给出中文说明，主路径是「等 CPU / 磁盘空下来后点面板状态条上的『重试』」，侧栏「运行设置 → 使用系统代理」只在「网络本来就必须走代理」时才需要（终端里 `export https_proxy` **不会**透传给子进程）。非超时的失败（退出码非 0 / 不可执行）**不重试**，避免启动耗时整整翻倍。超时预算未放宽。

### 工程侧（不影响使用）

- 开发构建的磁盘占用：两侧 `Cargo.toml` 给第三方依赖关掉调试信息（本机实测占依赖产物的 39%~89%），壳侧显式为核心保留调试帧；`[profile.release]` **一字未动**，交付产物不受影响。配合一次性清理，本机 `target` 从 14.1G 降到 2.8G。

## 安全与凭据纪律（不变量）

- 平台 Key 只经「平台」视图的保存动作进入核心，落盘数据目录 `providers.json`（`0600`，原子写）；除该文件外任何凭据不落盘、不进日志、不进 `status.json`、不进面板偏好（`localStorage` 白名单结构上装不下它）、不进子进程环境变量；
- 「平台」视图只显示「已配置 / 未配置」，明文与掩码都不回显，保存后面板不留副本；
- Key 只经 `OPENCODE_CONFIG_CONTENT` 通道进隔离的模型子进程，**不**进环境变量白名单；
- 全部路由仍强制 Bearer 鉴权（timing-safe 比较）、拒绝任何浏览器 Origin、仅监听 `127.0.0.1`、并发 ≤4、请求体 ≤8MB；
- 模型不得执行本地动作：原生工具一律 `ask`，`question`/`websearch`/`codesearch`/`webfetch`/`task`/`plan_*`/`todowrite` 为 `deny`，只能以 handoff 交回客户端；
- `open_external` 仅接受 https + RFC 3986 合法字符的 URL，不引入任何 WebView 侧网络请求（CSP 不放宽）。
