# WB Bridge v1.1.12 — 断开连接不再泄漏在途会话 ＋ 管理接口补齐读取预算 ＋ 面板无障碍一轮

## 本版主题

**这轮不做新功能，只把审查查出的真实缺陷改掉。** 三个核心侧问题、七个面板侧问题（下面合为 6 条：两处颜色算一条），全部有单测或实测数值支撑。

其中影响最大的是第一个：**客户端中途断开时，本工具的隔离服务里会留下一份永远无人回收的在途会话**。WorkBuddy / CodeBuddy 取消一次请求是日常操作（用户点停止、切会话、超时），每一次取消都在攒残留。

## 修复与改进

### 核心

1. **客户端断开后不再泄漏在途会话与权限轮询任务**：一次对话生成期间，核心除了转发内容，还会**每 250ms 轮询**该会话的原生工具待审批状态。原先清理逻辑写在生成函数的「正常结束 / 出错」路径上——而 hyper 在客户端断开时是**直接丢弃整个请求处理任务**，那条清理路径一行都不会执行。后果是每次断开发一个永不结束的轮询任务，并在状态表里留下一条会话记录（含 `usage_by_session`、待审批条目），活动流也停不掉。现改为**对象销毁即清理**的守卫：无论任务是正常返回、报错返回，还是被运行时丢弃，清理都会执行且只执行一次；异步收尾在当前 tokio 运行时上派发，拿不到运行时的理论路径只做同步清理。
2. **`/admin/*` 的请求体读取纳入与对话接口同一份 20 秒预算**：原先这份预算只挂在 `/v1/chat/completions` 外面那一层，五个管理入口（探测、代理开关、导入、刷新、三条平台 Key 动作）都没有它。管理路由不受「最多 4 并发」限制，因此一个只发头不发体的连接可以**无限期占住**该请求的任务与缓冲。现收拢到一个共用入口，一处生效。
3. **OpenCode 会话响应缺少会话 id 时当场失败，不再退化成空串**：原先取不到 id 会以空字符串继续，而**空串是一把会被共享的键**——两个并发请求会在会话状态表与用量表里落到同一个条目上互相干扰，删除路径也会退化成 `/session/`。现在这种情况直接返回错误。

### 面板

4. **两处颜色的对比度达标**（数值由 `src/styles/variables.css` 的 token 实算，不是目测）：
   - `--orange` 浅色模式 `#bc752c` → **`#a4581a`**。它同时用作 13px 的**错误正文**（反馈条、`.error-text`），原先在 `--orange-bg` 上只有 3.5:1，低于正文要求的 4.5:1；暗色模式的 `#e9ad70` 已达标，未动。
   - `--switch-off`（开关关闭态轨道）`#aab2ae` → **`#7f8a86`**。开关是可交互控件，按 WCAG 1.4.11 非文本对比需要 ≥3:1，原先在侧栏底色上不足；同时保住白色滑块与轨道的分界。
5. **十处小字号说明文字改用 `--muted-strong`**：视图副标题、页脚说明、模型行耗时、空列表提示、指标条说明、详情栏引导语、平台页的 id / 申请页网址 / 提示、关于页的版本说明。这些是 11–13px 的说明文字，原先用 `--muted` 在浅底上不到 4.5:1。**刻意没改**的两处：指标条的「空闲」是大字号（22px，按 3:1 已经过）、侧栏导航的色底（属装饰性色块，不是文字）。
6. **`Esc` 不再从输入框里抢走「收起详情」**：平台视图的 Key 输入框里按 Esc 是该控件自己的语义（清除 / 退出输入），此前会被全局收起详情吞掉。现在输入框、文本域、可编辑元素内的 Esc 一律放行。
7. **平台视图「读取免费模型（重新应用）」的成功提示真正会显示并自动消隐**：该分支原先只调了文案计算函数却没接上反馈状态，横幅**永不出现也永不消失**；顺带把「成功文案 5 秒自动消隐」这条与其它动作对齐。另：切走该视图时**清掉待触发的消隐定时器**，否则它会在 5 秒后往已卸载的组件状态上写值。
8. **忙态按「就是这个动作在飞」判定**：状态条的「重试」与集成页的「导入」原先在任何动作运行时都显示忙态（点了「刷新」也会让「导入」转起来），现各自看自己的动作名，并补上 `aria-busy`，读屏能知道按钮忙。
9. **空模型列表不再声明为列表角色**：`role="listbox"` 的直接子元素必须是选项，而空态那句「进行中」说明是 `role="status"`；列表为空时不再挂该角色，读屏不会把这句说明念成一项。
