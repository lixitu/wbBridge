# WB Bridge v1.1.2 — 多平台免费模型接入（自带 Key）＋ 稳定性与可用性修复

> **状态**: 📝 待发布（尚未构建、未打标签）
> **日期**: 2026-10-10
> **上一版本**: v1.0.2（GitHub 上实际 Publish 过的最后一个版本；其后的 `v1.0.3` ~ `v1.1.1` 均**未构建、未打标签**，本版把它们的内容一次性带上）

## 本版主题

**一、不再只有 OpenCode 自带的免费模型。** 新增「平台」视图：在面板里填入自己持有的平台 Key，即可把 **ModelScope（魔搭）**、**SiliconFlow（硅基流动）**、**腾讯混元 TokenHub**、**智谱** 四家平台的免费模型一起发现、探测并发布给 WorkBuddy / CodeBuddy。每张平台卡片内置三步申请指引与「打开官方申请页」按钮（系统浏览器打开）。Key 只保存在本机数据目录（`providers.json`，权限 0600），面板不回显、不做掩码、不进任何日志。不填任何 Key 时行为与上一版本完全一致（既有 `OC · ` 模型照常发布）。

**二、一批真实使用中暴露的问题被修掉**，包括：ModelScope 全部模型报「has no provider supported」、改一家 Key 却触发全部平台重读重检、上游英文报错（`not available in your country`、`Function call is not supported`、`Model … has been deprecated`）看不懂、重新检测没有过程反馈、插件配置目录里按发布次数堆积几十个 `.bak` 备份，以及**装了插件但从未保存过自定义模型时永远检测不到目标**（目录在、`models.json` 不在）——本版会在这种目录下自动补建一个空的 `models.json`。

## 新增功能

### 1. 面板「平台」视图

- 侧栏「模型」组新增入口，四家平台卡片恒常显示（不依赖核心在线），含「已配置 / 未配置」状态徽章；
- Key 输入框为密码型，保存后立即清空——面板不留任何副本；**保存 / 清除后自动热生效**：自动触发「读取免费模型」（只重启隔离的模型子进程，不动应用窗口），新 Key 随即注入并重新发现模型，无需重启应用；
- 每张卡片内置「申请 Key（三步）」指引与官方申请页直达按钮（经壳的 `open_external` 命令用系统浏览器打开；Tauri WebView 里 `target=_blank` 默认静默失败，外链必须经壳转发）；
- 底部「读取免费模型（重新应用）」为兜底手动入口：自动应用失败（如网络抖动）时可重试。

### 2. 多平台模型发现与发布（核心）

- **Key 注入**：启动时从 `providers.json` 读出已配置平台，以最小声明段 `{ npm, options: { baseURL, apiKey } }` 注入隔离配置（`OPENCODE_CONFIG_CONTENT` 通道）；Key 绝不进环境变量白名单、不进日志；
- **聚合发现**：在既有 `opencode` 命名空间之外，逐个已配置平台发现免费模型（CostZero 判定复用：输入/输出/缓存全 0 + 支持文本输出 + 未下线）；**单平台失败不丢其他平台**（失败只记日志）；
- **展示前缀**：新模型按平台显示，如 `ModelScope · …`、`智谱 · …`；模型行直接渲染真实 client id（顺带修复了此前模板硬编码 `OC · ` 的已知偏差）；
- **空发布集闸门**：一轮探测全部失败时拒绝清空 WorkBuddy / CodeBuddy 配置里本工具名下的条目并显式报错（关停 / 启动清旧 / 换配置文件三处用户意图清空不受影响）。

### 3. 各平台免费模型（2026-10-09 实测 catalog，随上游变动）

| 平台 | 免费模型数 | 代表模型 |
|---|---|---|
| ModelScope | 7 | GLM-4.6、Qwen3-235B 系列、Qwen3-Coder-30B |
| SiliconFlow | 3 | Qwen3.5-4B、DeepSeek-OCR、PaddleOCR-VL |
| 腾讯 TokenHub | 2 | Hy3、Hy3-preview |
| 智谱 | 3 | glm-4.5-flash、glm-4.7-flash、glm-4.6v-flash |

> 额度与可用性由各平台决定，本应用不缓存额度；探测与对话都会消耗平台侧额度（免费模型为 0 标价，仍受平台限额约束）。上游新增免费模型不会自动出现，随本应用注册表更新。

### 4. 插件目录已在、但没有 `models.json` 时自动补建

装了 WorkBuddy / CodeBuddy 却从未保存过自定义模型的机器上，数据目录（如 `~/.workbuddy`、`~/.codebuddy`）存在而 `models.json` 不存在，此前一律被判「未检测到」——插件装了，模型却永远发布不过去。本版在**默认位置**发现不到配置文件、但目录确实存在时，补建一个空的 `models.json`（内容 `[]`），随后正常发布。

补建的三条边界：文件已存在时绝不改写；目录不存在时**不替插件建目录**（目录不在＝没装，不能凭空造出「已安装」的假象）；写不进去（权限、只读盘）则静默跳过，按原样报「未检测到」。用户用环境变量或导入动作**显式指定**的位置不参与补建——那里失效必须照旧报未检测到。

## 修复与改进

1. **ModelScope 全部模型报 `has no provider supported`**：注入的声明段补上锚点条目 `models: { "wbbridge-provider-anchor": {} }`（该条目合成的幽灵模型按保留名过滤，不会进发布集）。
2. **改一家 Key 只重读重检那一家**：`/admin/probe` 支持 `{ providers: [...] }` 定向范围，其余平台的目录与探测结果一概不动；请求体形态不对时**当场拒绝**（不静默降级成全量，避免按整份目录消耗探测额度）。
3. **启动沿用上次结果**：启动后不再清空发布集、不再自动全量重读重检，直接用上一份目录与探测结果重新下发配置（顺带修掉端口漂移与 api-key 轮换后插件里仍是旧地址的问题）。代价如实说明：应用没在跑的那段时间，插件里本工具名下的模型指向已停掉的端点，请求会失败。
4. **重新检测有过程反馈了**：单模型「重新检测」在行内显示 spinner 与「检测中」并禁点，可与整批探测并发；反馈条在除「模型与服务」外的所有视图都可见（此前代理开关在平台 / 日志 / 用量 / 关于里失败了没地方显示）。
5. **上游英文报错改成可操作的中文说明**：`This model is not available in your country` → 说明这是按出口 IP 的地区拒绝、可到侧栏「运行设置 → 使用系统代理」换出口后重新检测（终端里 `export https_proxy` 不会透传给子进程）；`Model exo-free has been deprecated.` → 说明这是提供方撤架、不会被发布也不会重复消耗额度。错误码与 HTTP 状态逐字保留，都不触发重试。
6. **「不支持函数调用」不再整个丢弃模型**：上游明说该模型不支持函数 / 工具调用时，改为向它发一次真实纯对话请求，通了就按「仅对话」发布并在面板注记原因，不通照旧记失败——一个能正常对话的模型不再被判不可用。
7. **插件配置目录不再堆积备份**：写盘不再产生 `models.json.buddy-bridge-<毫秒>.bak`（从来没有读取方、面板也没有恢复入口，却按发布次数无限堆积），并会在同步时把旧版攒下的同族存量备份清掉，只删本工具自己那一种命名形态的文件，用户自己的 `*.bak` 不动。

## 安全与凭据纪律（不变量）

- Key 只经「平台」视图的保存动作进入核心，落盘 `providers.json`（0600，原子写）；除该文件外任何凭据不落盘、不进日志、不进 `status.json`、不进面板偏好（localStorage 白名单不含它）、不进子进程环境变量；
- 「平台」视图只显示「已配置 / 未配置」，明文与掩码都不回显；
- `open_external` 壳命令仅接受 https + RFC 3986 合法字符的 URL，用系统浏览器打开，不引入任何 WebView 侧网络请求（CSP 不放宽）。

## 下载与校验

CI 会产出六平台安装包与各自的 `.sig`（Ed25519，签名者 key ID = 配置里那条公钥 `2B11F78BEA8A43F`）。GitHub 会把资产名里的空格规范化成 `.`，页面上看到的名字形如：

- macOS：`WB.Bridge_1.1.2_aarch64.dmg`（Apple Silicon）/ `WB.Bridge_1.1.2_x86_64.dmg`（Intel）
- Windows：`WB.Bridge_1.1.2_x64-setup.exe`、`WB.Bridge_1.1.2_x64.msi`（及 arm64 同名形态）
- Linux：`WB.Bridge_1.1.2_amd64.AppImage`、`WB.Bridge_1.1.2_amd64.deb`（及 arm64 同名形态）

> 已安装旧版的用户可直接用应用内「检查更新」（`v1.0.2` 起才有更新器；`v1.0.1` 及更早只能重新下载安装包升级一次）。

## macOS 首次打开（ad-hoc 签名放行）

WB Bridge 为 ad-hoc 签名，**未做 Apple 公证**。首次打开（含更新后重新被拦截）提示「已损坏」时，确认来源可信后执行：

```bash
xattr -dr com.apple.quarantine "/Applications/WB Bridge.app"
```
